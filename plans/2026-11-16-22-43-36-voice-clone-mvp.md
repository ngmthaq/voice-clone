# Title: Plan — voice-clone MVP

- Classification: feature
- Description: Build a cross-platform Textual TUI that streams the mic through a small RVC engine of our own into BlackHole or VB-CABLE.

---

## Approach Summary / Goal

- Three developer sub-agents work **at the same time** on separate modules that share fixed interfaces: scaffold/config/devices, the RVC engine, and the audio pipeline. A fourth developer then builds the TUI and connects everything. After that, the tester writes the tests.
- The RVC engine copies the minimal inference files from the official RVC-Project repo (MIT license), so we load real RVC `.pth` voices without `fairseq`. ContentVec loads through `transformers`, and pitch comes from RMVPE. Both base models download from Hugging Face on first start.
- Goal: run `uv run voice-clone`, pick a mic, an output device and a voice, press Start. Zoom or Discord then hear the converted voice through the virtual device.

## Functional Requirements

- The app lists input devices and output devices, and selects BlackHole 2ch (macOS) or "CABLE Input" (Windows) by default when it finds one.
- It finds voice profiles in `voices/<name>/`: one `.pth` file, plus one `.index` file if there is one.
- On first start it downloads the base models to `models/` and shows progress in the TUI.
- Start and Stop control the live conversion. A pitch-shift setting goes from -12 to +12 semitones.
- Live level meters show the input and output volume.
- Settings (devices, profile, pitch) save to `settings.toml` in the user config folder and load again on the next start.
- Errors (no device, bad profile, failed download, failed model load) show in the TUI in plain words, and the app does not crash.

## Non-Functional Requirements

- Target delay is under about 300 ms on Apple Silicon (MPS) or an NVIDIA GPU (CUDA). The app falls back to CPU, which works but is slow.
- The audio callbacks never run the model, log, or block. The model runs in a worker thread. Blocks join with a crossfade, so there are no clicks.
- The app runs on macOS and Windows: paths use `pathlib`, and the code picks the torch device at run time.
- Logs go to a file in the user log folder, never to stdout.

## Risks & Assumptions

- **Assumption:** the base models come from `lengyue233/content-vec-best` (ContentVec in `transformers` format) and from `lj1995/VoiceConversionWebUI` → `rmvpe.pt`.
- **Assumption:** only RVC v2 voices (768-dim) are in scope, which are the common kind today. v1 (256-dim) voices also load if the copied code supports them, but nobody tests that.
- **Assumption:** the developer downloads the RVC source files from github.com/RVC-Project (MIT license) and keeps the license file.
- **Risk:** no real voice model is in the repo, so tests use random weights and a fake engine. Real voice quality and real delay need **one manual test by you**, with a real `.pth` voice and BlackHole installed.
- **Risk:** on Windows, CUDA torch needs the PyTorch package index. The plan sets this up in `pyproject.toml` with uv, but nobody can test it on this Mac.
- **Risk:** RVC streaming quality depends on the block size and context settings. The MVP uses fixed defaults (block 250 ms, past context 500 ms, crossfade 50 ms) and does not expose them in the UI.
- **Note:** Python 3.10 is on this machine, so the project sets `requires-python = ">=3.10,<3.13"` and uses `tomli` / `tomli-w` to read and write TOML.
